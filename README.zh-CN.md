# BiliNote Sync

将本机 BiliNote 生成成功的笔记与截图，按你的选择导入 Obsidian。它是独立的文件导入插件，不是 BiliNote 或 Obsidian 官方插件，也不负责视频转录和 AI 生成。

## 使用

1. 需要 Obsidian 桌面版 1.13.7 或更新版本，以及本机 BiliNote。实际验证环境是 Windows 和 BiliNote 桌面版 2.4.5；手机版、纯在线版和远程服务器结果不适用。
2. 到 **设置 → BiliNote Sync**，填写包含 `note_results` 和 `static` 的 BiliNote 安装目录。新安装不预填某台电脑的路径。
3. 在 BiliNote 生成成功后，在命令面板搜索 **选择导入 BiliNote 笔记**，勾选需要的笔记，再点击 **导入选中**。也可以用左侧图标或设置中的“选择笔记”。

新安装默认关闭自动同步，开启打开仓库时的选择提醒。提醒只显示窗口，默认不勾选、不自动导入；关闭窗口即可跳过。Obsidian 运行期间新生成的笔记可手动选择。需要全部自动导入时，可开启“自动同步全部笔记”，插件每 10 秒检查一次；关闭软件时不运行。

原笔记和你的编辑不会被覆盖；内容更新会另存一份。删除后的笔记可以手动选中重新导入，自动模式不会反复恢复同一任务的同一版本。重命名或移动会根据笔记属性恢复记录，请保留 `bilinote_task` 和 `bilinote_source_hash`。

## 图片与清理

新安装默认使用独立图片副本。开启“共用图片数据”后，同一文件系统优先建立硬链接，两个路径共用图片内容；**直接修改图片会影响两端**。不支持硬链接时使用副本。

新安装默认关闭音视频清理。开启后，只有笔记和截图核对完整，才会**永久删除** BiliNote `data` 目录内能确认归属的下载音视频，不经过回收站。重新生成或补截图可能需要重新下载。原始视频应保存在缓存目录之外。

每集独立判断：其他分集仍在生成时，已完成并导入的分集可以清理。同一份音视频仍有排队、生成、失败待重试或未导入的任务使用时会保留。已明确移除的失败任务不再占用引用；正在运行的任务即使从历史移除也继续保护。旧版首集文件名与带 `_p1` 的首集文件名一起核对，避免遗漏共享结果。

未知名称、路径重定向、符号链接、刚写入或正在变化的文件会保留。完成结果损坏、缺少状态时仍保护对应缓存；任务无法确定视频或合集记录异常时暂缓删除。删除前再次核对任务与文件，但插件与 BiliNote 没有共同的事务锁，其他程序直接改写缓存期间应关闭清理。选择导入时仅考虑所选视频；“立即清理”不会顺带导入别的笔记。

升级会保留你之前保存的图片共用和清理选项。

## 隐私

插件不调用网络、不调用大模型、不消耗 Token，也不读取 BiliNote 的 API Key、Cookie、数据库、`.env` 或模型配置。它读取你配置的仓库外结果、状态和截图；清理功能另外读取音频元数据、`note_results/task_requests`、`note_results/series_batches` 与 `note_results/series_task_removals.json`，判断排队、失败、已移除等任务，并删除符合条件的下载缓存。这些记录只在本机处理，不上传。笔记、附件写入仓库，设置与导入记录保存在插件自己的 `data.json`。移动笔记的恢复检查可能读取仓库内其他 Markdown 文件。

源正文已有的外部链接与远程图片会保留，Obsidian 展示笔记时可能按其自身行为加载远程图片。插件本身不抓取这些链接。

社区审核会提示“直接访问文件系统”和“遍历仓库文件”：前者用于读取你指定的 BiliNote 本机结果，后者用于找回已移动的笔记。这些访问范围在上面披露。

## 构建与发布

源码位于 `src/plugin.cjs` 和 `src/plugin.css`。`npm run build` 会生成根目录的安装文件，以及 `.release/1.4.3/` 中的三个发布文件；即使旧的 `main.js` 和 `styles.css` 被移除，也能重新构建。新增 24 个隔离测试，验证独立分集清理、缓存共享、失败重试、异常记录和最后检查期间的改写；测试只用合成文件，不操作真实仓库。

GitHub Actions 会在 Windows、Linux 上运行检查。推送与 manifest 一致的版本标签后，流水线为三个安装文件生成并验证 GitHub 来源证明，再公开发布。无需把个人密钥写入仓库。

插件代码采用 MIT 许可证；BiliNote 的代码、安装包与个人数据均未包含在发布项目中。完整说明、限制和开发命令见 [README.md](README.md)；上架步骤见 [PUBLISHING.md](PUBLISHING.md)。
